# الباك إند — تطبيق المهام اليومية (Laravel)

هذا المستودع يحتوي على واجهة برمجية خلفية (API) لتطبيق يساعد المستخدمين على تنظيم المهام اليومية ومتابعة التقدم والأنشطة المرتبطة بها. تم تصميم المشروع باستخدام Laravel، مع مراعاة فصل الإعدادات الحساسة عن الشيفرة المصدرية.

## نبذة عن المشروع

يوفّر النظام مجموعة من الخدمات لإدارة:

- حسابات المستخدمين وتسجيل الدخول.
- التصنيفات المستخدمة لتنظيم المحتوى.
- الخطط الدراسية أو خطط العمل اليومية.
- المهام اليومية وتحديث حالتها عند الإنجاز.
- التذكيرات المرتبطة بالمهام.
- جلسات الرياضة وتسجيل إكمالها.
- ملخصات التقدم والمزامنة بين البيانات.

تتواصل تطبيقات الواجهة الأمامية مع النظام عبر API منظمة، ويمكن اختبار نقاط النهاية باستخدام ملفات Postman الموجودة في مجلد `postman`.

## التقنيات

- **Laravel / PHP** لبناء خدمات الخلفية.
- **REST API** للتكامل مع تطبيقات الويب أو الهاتف.
- **Postman** لاختبار الطلبات والاستجابات.
- دعم رسائل الاستجابة باللغة العربية افتراضيًا، مع إمكانية طلبها باللغة الإنجليزية باستخدام الهيدر `Accept-Language: en`.

## المتطلبات

قبل تشغيل المشروع، تأكد من توفر:

- PHP بالإصدار المتوافق مع نسخة Laravel المستخدمة.
- Composer.
- قاعدة بيانات مناسبة للمشروع.
- امتداد PHP المطلوب من Laravel وقاعدة البيانات.

## التشغيل محليًا

1. ثبّت الاعتماديات:

   ```bash
   composer install
   ```

2. أنشئ ملف إعدادات البيئة:

   ```bash
   cp .env.example .env
   ```

   في أنظمة Windows يمكن نسخ الملف يدويًا باسم `.env`.

3. أنشئ مفتاح التطبيق:

   ```bash
   php artisan key:generate
   ```

4. حدّث إعدادات قاعدة البيانات داخل `.env` باستخدام قيم محلية أو قيم محفوظة بأمان.

5. شغّل الترحيلات عند الحاجة:

   ```bash
   php artisan migrate
   ```

6. شغّل الخادم المحلي:

   ```bash
   php artisan serve
   ```

   سيكون العنوان المحلي الافتراضي عادةً:

   ```text
   http://127.0.0.1:8000
   ```

## اختبار الـ API

توجد تعليمات وملفات Postman في مجلد [`postman`](postman). وبشكل عام:

1. استورد مجموعة الطلبات وبيئة التشغيل المحلية في Postman.
2. شغّل الخادم المحلي.
3. اضبط عنوان API الأساسي على:

   ```text
   http://127.0.0.1:8000/api/v1
   ```

4. ابدأ بالتسجيل أو تسجيل الدخول للحصول على رموز الوصول.
5. أنشئ البيانات بالترتيب المناسب، مثل التصنيفات والخطط ثم المهام.
6. استخدم رموز الوصول التي يتم الحصول عليها تلقائيًا في بقية الطلبات.

عند إرسال طلبات `POST` أو `PUT` أو `PATCH`، يجب اختيار `Body` ثم `raw` ثم `JSON` في Postman حتى تتمكن Laravel من قراءة الحقول بشكل صحيح.

## ملاحظات حول الاستجابات

- أخطاء التحقق من البيانات تعاد عادةً برمز `422`، ويمكن مراجعة `error.details` لمعرفة الحقول غير الصحيحة.
- الخطأ `400 INVALID_JSON` يعني أن جسم الطلب ليس JSON صالحًا.
- أخطاء الموارد غير الموجودة، مثل `CATEGORY_NOT_FOUND` أو `TASK_NOT_FOUND`، تعني أن المعرّف المرسل غير صحيح أو أن السجل لم يُنشأ بعد.

## حماية المعلومات الحساسة

- لا تضع كلمات المرور أو مفاتيح الخدمات أو رموز الوصول أو بيانات قواعد البيانات داخل المستودع.
- استخدم ملف `.env` للإعدادات المحلية، وتأكد من أنه مضاف إلى `.gitignore`.
- لا ترفع ملفات Postman التي تحتوي على رموز حقيقية أو بيانات مستخدمين حقيقية.
- استخدم قيمًا وهمية أو أمثلة عامة في التوثيق والاختبارات.
- عند مشاركة سجلات الأخطاء أو لقطات الشاشة، احذف الرموز والمفاتيح والمعرّفات والبيانات الشخصية قبل نشرها.

## هيكل مختصر

- `app/` — منطق التطبيق والخدمات والنماذج.
- `routes/` — تعريف مسارات API.
- `database/` — الترحيلات والبيانات التجريبية عند وجودها.
- `config/` — إعدادات Laravel.
- `postman/` — ملفات اختبار API وتعليمات استخدامها.
- `.env.example` — نموذج للإعدادات المطلوبة دون قيم سرية.
