# الباك إند — تطبيق المهام اليومية (Laravel)

هذا المستودع يحتوي على الواجهة الخلفية لتطبيق يساعد المستخدمين على تنظيم المهام اليومية، متابعة الإنجاز، والاطلاع على ملخصات التقدم من خلال واجهة برمجية (API) منظمة وقابلة للتكامل مع تطبيقات الويب أو الهاتف.

> يركّز هذا التوثيق على شرح وظيفة المشروع وطريقة تشغيله دون تضمين أي أسرار أو بيانات تشغيل حساسة.

## نبذة عن المشروع

يوفّر النظام خدمات لإدارة دورة المهام اليومية، بما في ذلك:

- إنشاء حسابات المستخدمين وتسجيل الدخول وإدارة جلسات الوصول.
- إنشاء التصنيفات واستخدامها لتنظيم المهام.
- إعداد الخطط الدراسية أو خطط العمل اليومية.
- إنشاء المهام وتحديث حالتها عند الإنجاز.
- جدولة التذكيرات المرتبطة بالمهام.
- تسجيل جلسات الرياضة ومتابعة إكمالها.
- عرض ملخصات التقدم.
- مزامنة البيانات بين مكونات التطبيق عند الحاجة.

تتواصل الواجهات الأمامية مع الخدمات من خلال REST API. ويمكن استخدام ملفات Postman الموجودة في مجلد `postman/` لاختبار تدفق الاستخدام الأساسي محليًا.

## التقنيات المستخدمة

- **Laravel / PHP** لبناء منطق التطبيق وخدمات الخلفية.
- **REST API** للتكامل مع تطبيقات الويب والهاتف.
- **قاعدة بيانات** لتخزين المستخدمين والخطط والمهام والتذكيرات وسجلات التقدم.
- **Postman** لاختبار الطلبات والاستجابات.
- دعم رسائل الاستجابة باللغة العربية افتراضيًا، مع إمكانية طلب الرسائل باللغة الإنجليزية باستخدام الهيدر `Accept-Language: en`.

## التشغيل محليًا

1. ثبّت الاعتماديات:

   ```bash
   composer install
   ```

2. أنشئ ملف إعدادات البيئة من النموذج:

   ```bash
   cp .env.example .env
   ```

   في أنظمة Windows يمكن نسخ `.env.example` يدويًا وتسميته `.env`.

3. أنشئ مفتاح التطبيق:

   ```bash
   php artisan key:generate
   ```

4. حدّث إعدادات قاعدة البيانات داخل `.env` باستخدام قيم محلية أو قيم محفوظة في مدير أسرار آمن.

5. شغّل الترحيلات عند الحاجة:

   ```bash
   php artisan migrate
   ```

6. شغّل الخادم المحلي:

   ```bash
   php artisan serve
   ```

العنوان المحلي الافتراضي عادةً:

```text
http://127.0.0.1:8000
```

## اختبار الـ API

توجد ملفات وتعليمات Postman في مجلد [`postman`](postman). لاختبار التدفق الأساسي:

1. استورد مجموعة الطلبات وبيئة ا��تشغيل المحلية في Postman.
2. شغّل الخادم المحلي.
3. اضبط عنوان API الأساسي على:

   ```text
   http://127.0.0.1:8000/api/v1
   ```

4. ابدأ بالتسجيل أو تسجيل الدخول للحصول على رموز الوصول.
5. أنشئ البيانات بالترتيب المناسب، مثل التصنيفات والخطط ثم المهام.
6. استخدم رموز الوصول التي تُحفظ تلقائيًا في متغيرات Postman لبقية الطلبات.

عند إرسال طلبات `POST` أو `PUT` أو `PATCH`، اختر في Postman:

`Body` → `raw` → `JSON`

حتى تتمكن Laravel من قراءة الحقول المرسلة بشكل صحيح.

## تسلسل استخدام مقترح

يمكن اختبار المكونات بالترتيب التالي:

1. التسجيل أو تسجيل الدخول.
2. إنشاء تصنيف.
3. إنشاء خطة يومية.
4. إنشاء مهمة ثم تحديثها عند الإنجاز.
5. إنشاء تذكير مرتبط بمهمة.
6. إنشاء جلسة رياضية ثم تسجيل إكمالها.
7. استعراض التقدم وتجربة المزامنة.

## الاستجابات والأخطاء

- أخطاء التحقق من البيانات تُعاد ��ادةً برمز `422`. راجع `error.details` لمعرفة الحقول غير الصحيحة.
- الخطأ `400 INVALID_JSON` يعني أن جسم الطلب ليس JSON صالحًا أو أن نوع Body في Postman غير صحيح.
- أخطاء الموارد غير الموجودة، مثل `CATEGORY_NOT_FOUND` أو `TASK_NOT_FOUND`، تعني أن المعرّف المرسل غير صحيح أو أن السجل لم يُنشأ بعد.
- يمكن طلب الرسائل الإنجليزية بإضافة:

  ```http
  Accept-Language: en
  ```

## هيكل المشروع

- `app/` — منطق التطبيق والخدمات والنماذج.
- `routes/` — تعريف مسارات API.
- `database/` — الترحيلات والبيانات التجريبية عند توفرها.
- `config/` — إعدادات Laravel.
- `postman/` — ملفات اختبار API وتعليمات استخدامها.
- `.env.example` — نموذج للإعدادات المطلوبة دون قيم سرية.

## حماية المعلومات الحساسة

للحفاظ على سرية المشروع وبيانات مستخدميه:

- لا تضع كلمات المرور أو مفاتيح الخدمات أو رموز الوصول أو بيانات قواعد البيانات داخل المستودع.
- استخدم `.env` للإعدادات المحلية، وتأكد من بقائه خارج Git عبر `.gitignore`.
- لا ترفع ملفات Postman التي تحتوي على رموز حقيقية أو بيانات مستخدمين حقيقية.
- استخدم قيمًا وهمية وأمثلة عامة في التوثيق والاختبارات.
- عند مشاركة سجلات الأخطاء أو لقطات الشاشة، احذف الرموز والمفاتيح والمعرّفات والبيانات الشخصية.
- لا تذكر في التوثيق معلومات داخلية غير ضرورية، مثل عناوين الخوادم الخاصة أو بيانات الاعتماد أو تفاصيل البنية الأمنية.
- إذا تم كشف سر بالخطأ، أبطله أو غيّره فورًا، ثم أزل أثره من السجل وفق إجراءات المشروع.
